# 2026-03-17 3Dマインスイーパー開発における技術的課題と解決策の記録

## 概要
3Dマインスイーパーの開発において、Streamlit Cloud（特に Python 3.13 環境）特有の `TypeError` およびデータ構造の変更に伴う `AttributeError` に直面しました。これらを解決したプロセスと、今後の開発に活かすべき教訓を記録します。

## 1. Streamlit HTML コンポーネントの TypeError 問題
### 課題
`st.components.v1.html` を使用して 3D 描画（Three.js）を行おうとした際、コードに論理的な誤りがないにもかかわらず `TypeError` が発生し続けました。

### 原因の特定
- **f-string と CSS/JS の衝突**: `f"""<style>{css}</style>"""` のように f-string 内で波括弧 `{ }` を含む文字列を展開すると、Python がそれを変数補完と誤認し、複雑な文字列構造においてパースエラー（TypeError）を引き起こす。
- **巨大な JSON のシリアライズ**: Pydantic モデルを JSON 化した数万〜数十万文字の巨大な文字列を HTML 内の JavaScript 関数引数として直接埋め込むと、Streamlit の通信レイヤー（Protobuf）で処理不能な状態になりエラーとなる。

### 解決策（ベストプラクティス）
1. **`.replace()` による安全な置換**: f-string を避け、ユニークなプレースホルダー（例: `__M3D_JSON__`）を用いた `.replace()` 方式でアセットを埋め込む。
2. **JSON データの「隔離」**: データを JS 関数の引数に直接書くのではなく、`<script type="application/json">` タグに配置し、JS 側で `document.getElementById().textContent` から取得して `JSON.parse` する。これにより、引用符や特殊文字による HTML 破壊も防げる。
3. **データ構造の軽量化**: 辞書形式（`dict`）はキーの重複により JSON が肥大化しやすいため、可能な限りフラットなリスト形式（`list`）で管理する。

## 2. Pydantic モデル変更時の AttributeError
### 課題
データ軽量化のためにモデルのフィールド名を変更した際、UI 側の参照箇所の修正が漏れ、ランタイムエラーが発生しました。

### 教訓
- **UI とロジックの同期**: モデルの破壊的変更（フィールド名変更）を行う際は、必ず `grep` 等を使用してプロジェクト全体の参照箇所を確認すること。
- **テストの網羅性**: ロジックだけでなく、UI 層で行っている計算（例: `opened_count` の集計）もテスト対象に含める、またはロジック層のメソッドとして抽出し、ユニットテストで保護すること。

## 3. 今後の開発指針
- **HTML コンポーネントを使う場合**: データの受け渡しは常に `application/json` スクリプトタグを介して行う。
- **複雑な HTML 生成**: ページ（UI層）ではなく、ロジック層（`src/utils`）のクラスメソッドとして `generate_safe_html` 等を定義し、テスト可能な状態に保つ。
