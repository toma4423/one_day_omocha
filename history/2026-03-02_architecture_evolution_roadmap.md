# 次世代アーキテクチャへの移行準備と開発ルールの厳格化 (2026-03-02)

## 概要
「One Day Omocha」のコンセプトである開発スピードを維持しつつ、将来的な **FastAPI**（バックエンド）および **Kotlin/Compose Multiplatform**（モバイル）への移行をスムーズに行うため、プロジェクトのアーキテクチャを「API-First」の設計にシフトします。

## 意思決定事項
1.  **フレームワーク移行のロードマップ**: 
    - 短期的には Streamlit を継続使用するが、ロジック層を完全に API 化（疎結合化）する。
    - 中長期的にはロジックを FastAPI へ、UI を React や Kotlin へ分離可能な構造にする。
2.  **Pydantic の導入**: データの入出力を厳格に定義するため、Pydantic モデルをデータコンテナとして採用する。
3.  **UI とロジックの完全隔離**: 既存の `src/utils` をさらに純粋化し、Web フレームワークに依存しない「ビジネスロジックの集合体」へと進化させる。

## リファクタリングおよび開発の新ルール
- **Data over Primitives**: 関数に多数の引数を渡すのではなく、Pydantic モデルや TypedDict でカプセル化したデータを渡す。
- **Zero Side Effects in Utils**: `src/utils` の関数は外部状態（SessionState, Global Variables）を一切参照せず、与えられた入力からのみ出力を計算する。
- **Error Handling at Logic Layer**: 異常系の判定はロジック層で完結させ、UI層には明確なエラーオブジェクトを返す。

## 理由
- 現状の Streamlit 依存の設計では、UI の高度化に伴う「iframe 制限」や「リロード時の状態消失」に対応しきれなくなってきているため。
- 今のうちにロジックを API 形状に整えておくことで、将来 FastAPI に移行する際、コードの 90% 以上をそのまま移植できるようにするため。
